## 최종 분석 — 7교시에 완성합니다

> 오늘 잡은 **내 HTTP 연결 하나**를 처음부터 끝까지 정리합니다. 위에서 적은 6-3 · 7-1 · 7-2 의 답을 다시 보며 씁니다.

### 1. 연결이 열리는 순간 — 3-way handshake

- 세 줄의 Source → Destination 과 Info:
1.내 PC → 서버: SYN
2.서버 → 내 PC: SYN, ACK
3.내 PC → 서버: ACK
- 세 줄이 오간 뒤 두 컴퓨터는 어떤 상태가 되나요?
  - 답:
세 번의 신호가 오가면 TCP 연결이 성립되어 두 컴퓨터가 데이터를 주고받을 수 있는 ESTABLISHED 상태가 됩니다.
### 2. 패킷 하나를 열어 본 값 — 6-3

- 출발지 · 목적지 IP (3층) · TTL · 출발지 · 목적지 포트 (4층):
출발지 IP: 192.168.100.251 (내 PC인 경우)
목적지 IP: Wireshark에서 확인한 서버 IP
TTL: Wireshark에서 확인한 값
출발지 포트: Wireshark에서 확인한 값
목적지 포트: Wireshark에서 확인한 값
- 목적지 포트를 보고 어떤 서비스로 가는 패킷인지 알 수 있나요? 4.1 표를 근거로 설명합니다.
  - 답:
  목적지 포트 번호를 4.1 표와 비교하면 어떤 서비스로 향하는 패킷인지 추측할 수 있습니다. 예를 들어 목적지 포트가 80이면 일반적으로 HTTP, 443이면 HTTPS 서비스로 향하는 패킷입니다.

### 3. HTTP 요청 — 7-2

- 요청 줄에서 그대로 보인 내용:
내가 검색한 검색어와 HTTP 요청 정보
- 이것이 보안에서 문제가 되는 이유는 무엇인가요?
  - 답:
HTTP는 통신 내용을 암호화하지 않기 때문에 네트워크를 중간에서 관찰할 수 있는 사람이 검색어, 요청 경로 등의 정보를 확인할 수 있습니다. 로그인 정보나 개인정보가 포함되면 유출될 위험이 있으므로, 통신 내용을 암호화하는 HTTPS를 사용하는 것이 중요합니다.

- 오늘 배운 것 가운데 가장 중요하다고 생각하는 것과 그 이유:
오늘 배운 것 중 가장 중요하다고 생각하는 것은 Wireshark를 이용한 패킷 분석입니다. 네트워크 통신의 방향과 연결 상태, 요청 내용을 직접 확인할 수 있고, HTTP와 HTTPS의 차이 및 보안 위험을 이해하는 데 도움이 되기 때문입니다.
