# 2일차 네트워크 설계 보고서

## 3교시 · 내 서브넷과 망 범위

### 문제 3-1 · 내 서브넷 마스크 읽기

- (가-1) 내 서브넷 마스크 · CIDR · 주소 수 · 쓸 수 있는 수
  - 서브넷 마스크: `255.255.0.0`
  - CIDR: `/16`
  - 전체 주소 수: 65,536개
  - 장비에 쓸 수 있는 주소 수: 65,534개

- (가-2) 내 IPv4 주소의 망 부분 · 장비 부분
  - IPv4 주소: `192.168.100.251`
  - 망 부분: `192.168`
  - 장비 부분: `100.251`
  - 이유: `/16`은 앞의 두 마디가 망 부분이고 뒤의 두 마디가 장비 부분이다.

- (나-1) 2진수에서 1과 0의 의미
  - `255.255.0.0`을 2진수로 바꾸면 `11111111.11111111.00000000.00000000`이다. 앞의 16비트는 망 부분이고 뒤의 16비트는 장비 부분이다.

- (나-2) CIDR 계산
  - `255` 하나는 2진수로 `11111111`이므로 1이 8개다. `255`가 두 개이므로 `8 × 2 = 16`이며 CIDR은 `/16`이다.

- (나-3) 같은 교실 PC와 비교
  - 같은 망에 있는 PC는 망 부분이 같고 장비 부분은 서로 다를 수 있다. 망 부분은 어느 망인지, 장비 부분은 그 망 안의 어느 장비인지 나타낸다.

- (다-1) `192.168.10.25`와 `192.168.20.25`의 같은 망 여부
  - `/16`에서는 앞의 두 마디를 비교한다. 두 주소의 망 부분이 모두 `192.168`이므로 같은 망이다.

- (다-2) `/24`로 판정하면?
  - `/24`에서는 앞의 세 마디를 비교한다. `192.168.10`과 `192.168.20`은 다르므로 다른 망이다.

- (다-3) 마스크에 따라 판정이 달라지는 이유
  - 서브넷 마스크에 따라 같은 망인지 다른 망인지 달라진다. 같은 망이면 일반적으로 직접 통신하고, 다른 망이면 게이트웨이를 통해 통신한다. 방화벽 규칙에도 영향을 주므로 올바른 마스크를 확인해야 한다.

### 문제 3-2 · 내 망 범위

- (가) 두 번째 파일의 주소/CIDR 및 출력
  - 내 주소/CIDR: `192.168.100.251/16`
  - 서브넷 마스크: `255.255.0.0`
  - 네트워크 주소: `192.168.0.0`
  - 브로드캐스트 주소: `192.168.255.255`

- (나-1) 출력 세 줄의 의미
  - 첫째 줄: 서브넷 마스크
  - 둘째 줄: 네트워크 주소
  - 셋째 줄: 브로드캐스트 주소

- (나-2) 0과 255로 바뀐 마디
  - 네트워크 주소에서는 셋째와 넷째 마디가 `0`으로 바뀐다. 브로드캐스트 주소에서는 셋째와 넷째 마디가 `255`로 바뀐다.

- (나-3) AND 연산 설명
  - IP 주소 `192.168.100.251`과 마스크 `255.255.0.0`을 AND 연산한다. 마스크가 255인 앞 두 마디는 그대로 남고, 마스크가 0인 뒤 두 마디는 0이 된다. 결과는 `192.168.0.0`이다.

- (나-4) 일부 마디만 바뀌는 이유
  - `/16`에서는 앞의 두 마디가 망 부분이고 뒤의 두 마디가 장비 부분이다. 따라서 망 부분은 유지되고 장비 부분만 바뀐다.

- (다-1) 기본 게이트웨이가 주소 범위 안에 있는가?
  - 수업 자료에 나온 기본 게이트웨이 `192.168.1.1`을 기준으로 하면 예이다. 네트워크 주소 `192.168.0.0`과 브로드캐스트 주소 `192.168.255.255` 사이에 있다.

- (다-2) 게이트웨이가 범위 안에 있어야 하는 이유
  - PC가 게이트웨이와 같은 망에서 통신할 수 있어야 다른 망으로 패킷을 전달할 수 있기 때문이다.

- (다-3) 네트워크 주소나 브로드캐스트 주소를 게이트웨이로 설정하면?
  - 네트워크 주소는 망 자체를 나타내고 브로드캐스트 주소는 망 안의 모든 장비를 대상으로 한다. 둘 다 개별 장비의 주소가 아니므로 게이트웨이 주소로 적절하지 않다.

## 4교시 · 서브네팅

### 문제 4-1 · `/25`로 반으로 나누기

- (가) 출력 두 줄
  - `192.168.50.0/25`
  - `192.168.50.128/25`

- (나-1) 블록별 주소 범위
  - 블록 1: `192.168.50.0` ~ `192.168.50.127`
  - 블록 2: `192.168.50.128` ~ `192.168.50.255`

- (나-2) `192.168.50.128/25`에서 `/` 앞 주소의 의미
  - `192.168.50.128`은 해당 블록의 네트워크 주소이며 블록이 시작하는 주소다.

- (나-3) 두 블록이 `.128`에서 나뉘는 이유
  - `/25` 블록 하나에는 주소가 128개 있다. 첫 블록은 `.0`부터 `.127`까지이므로 다음 블록은 `.128`에서 시작한다.

- (나-4) 쓸 수 있는 주소 수인 126개만큼 자르면 안 되는 이유
  - 블록은 장비에 쓸 수 있는 주소 수가 아니라 네트워크 주소와 브로드캐스트 주소를 포함한 전체 주소 수 128개를 기준으로 나눈다.

- (다-1) `/26`의 주소 수와 장비에 쓸 수 있는 수
  - 전체 주소 수: 64개
  - 장비에 쓸 수 있는 주소 수: 62개

- (다-2) 두 수가 2만큼 다른 이유
  - 네트워크 주소와 브로드캐스트 주소는 일반 장비에 할당하지 않으므로 2개를 제외한다.

- (다-3) 장비가 64대인 부서에 `/26`을 주면?
  - 장비에 쓸 수 있는 주소는 62개뿐이므로 64대를 모두 수용할 수 없다. 더 큰 블록인 `/25`를 선택해야 한다.

### 문제 4-2 · 겹침 검사

- (가) 두 파일의 출력
  - `warmup_4_2.py`: `False`
  - `warmup_4_2b.py`: `True`

- (나-1) `True`가 나온 이유
  - 개발팀 범위는 `192.168.50.0` ~ `192.168.50.127`이고 운영팀 범위는 `192.168.50.64` ~ `192.168.50.127`이다. 운영팀의 범위가 개발팀 범위 안에 포함되므로 두 망이 겹친다.

- (나-2) 겹치는 주소 구간
  - `192.168.50.64` ~ `192.168.50.127`

- (다-1) 같은 IP를 두 장비에 할당하면?
  - IP 주소 충돌이 발생해 통신이 끊기거나 불안정해질 수 있다.

- (다-2) 관제 로그 해석에 생기는 문제
  - 여러 장비가 같은 IP를 사용하면 로그만으로 실제 장비를 구분하기 어려워져 사고 원인 분석과 추적이 어려워진다.

## 5교시 · 스위치와 라우터

### 핵심 정리
- 스위치는 같은 망 안에서 MAC 주소를 기준으로 프레임을 전달한다.
- 라우터는 서로 다른 망 사이에서 IP 패킷을 전달한다.
- 같은 망의 장비끼리는 일반적으로 스위치를 통해 통신한다.
- 다른 망의 장비와 통신할 때는 기본 게이트웨이를 이용한다.

### 문제 5 · 확인 내용
- 같은 망과 다른 망의 통신 경로는 다르다.
- 다른 망으로 보낼 패킷은 기본 게이트웨이로 전달된다.
- `tracert`의 첫 번째 홉은 일반적으로 경로상 첫 라우터를 보여 준다.

## 6교시 · VLAN

### 핵심 정리
- VLAN은 하나의 물리적 스위치 환경을 논리적으로 여러 망으로 나누는 기능이다.
- 같은 스위치에 연결되어 있어도 VLAN이 다르면 일반적으로 서로 다른 망으로 취급한다.
- 서로 다른 VLAN 사이의 통신에는 라우터 또는 레이어 3 스위치의 라우팅이 필요하다.
- VLAN은 부서별 망 분리와 통신 관리에 활용된다.

### 문제 6 · 확인 내용
- 같은 VLAN인지 다른 VLAN인지 확인한다.
- VLAN이 다르면 같은 스위치에 연결되어 있어도 라우팅이 필요할 수 있다.
- 네트워크 설계에서는 IP 주소, 서브넷 마스크, 기본 게이트웨이, VLAN 설정을 함께 확인해야 한다.

### 문제 7-3 · 설계서 완성하고 올리기
